Chat Cliente-Servidor con Sockets y SQLite

Programación de Redes - Servidor TCP Multihilo con Asignación de ID y Persistencia

🎯 Objetivo del Programa

Aprender a configurar un servidor de sockets en Python que reciba mensajes de clientes, los almacene en una base de datos y envíe confirmaciones, aplicando buenas prácticas de modularización, concurrencia multihilo y manejo de errores.

🔌 Sockets TCP/IP

Comunicación orientada a la conexión con socket.AF_INET y socket.SOCK_STREAM.

🆔 Asignación de Identificador

Cada cliente que se conecta recibe automáticamente un ID único (ej: Cliente-1, Cliente-2).

💾 Persistencia SQLite

Cada mensaje se guarda de forma persistente en mensajes.db con ID, contenido, fecha e IP.

📨 Confirmaciones al Cliente

El servidor responde con un acuse de recibo notificando el ID del mensaje guardado y la fecha/hora.

🗄️ Esquema de la Base de Datos (`mensajes.db`)

Campo Tipo Descripción
id INTEGER PRIMARY KEY AUTOINCREMENT Identificador secuencial del mensaje
id_cliente TEXT NOT NULL Identificador asignado al cliente (ej: Cliente-1)
contenido TEXT NOT NULL Texto del mensaje enviado
fecha_envio TEXT NOT NULL Timestamp de envío (YYYY-MM-DD HH:MM:SS)
ip_cliente TEXT NOT NULL Dirección IP del cliente
puerto_cliente INTEGER NOT NULL Puerto de conexión del cliente

💡 Respuestas Conceptuales

1. ¿Por qué hashear contraseñas?

Almacenar contraseñas en texto plano es una de las vulnerabilidades más críticas en seguridad. Si la base de datos se ve comprometida (inyecciones SQL, backups expuestos o accesos indebidos), todos los datos de los usuarios quedan vulnerados.


El hasheo criptográfico resuelve esto porque:

  • Es de sentido único (One-Way): Es computacionalmente inviable revertir el hash para descubrir la contraseña.
  • Incorpora Salting: Agrega un valor aleatorio único por usuario para anular ataques con Tablas Arcoíris (Rainbow Tables).
  • Factores de coste: Algoritmos modernos como scrypt o PBKDF2 hacen inviable el ataque masivo por fuerza bruta.
2. Ventajas de usar SQLite en este proyecto
  • Serverless (Sin Servidor): Funciona directamente en el proceso de la aplicación sin necesidad de configurar un daemon o servicio independiente (como Postgres o MySQL).
  • Autocontenido y Portable: Toda la base de datos es un único archivo físico (mensajes.db), facilitando el traslado y evaluación del proyecto.
  • Nativo en Python: Viene preinstalado en la librería estándar (import sqlite3), sin requerir dependencias externas.
  • Transaccional (ACID): Asegura integridad y atomicidad completa ante fallos o apagados inesperados.

🚀 Guía de Ejecución

# 1. En una terminal, iniciar el servidor:
python servidor.py

# 2. En otra(s) terminal(es), conectar clientes:
python cliente.py
